# Sorting & Hash Patterns

**適用条件:** ソート、順序統計、頻度カウント、ハッシュマップ/set

## ソート関連

| パターン | 検出目的 | 例 |
|---------|---------|-----|
| 昇順済み | 二重ソート不要 | `[1,2,3,4]` |
| 降順済み | 最悪入力の一種 | `[4,3,2,1]` |
| 全要素同一 | 比較回数・安定性 | `[5,5,5,5]` |
| 重複多数 | 安定ソート要否 | `[2,2,2,1,1]` |
| クイックソート最悪 | O(N²) | 昇順/降順で pivot 最悪 |
| N=0, N=1 | ベース | `[]`, `[1]` |
| カスタム comparator | tie-break 漏れ | 同一キーで第二キー |

## ハッシュ / カウント関連

| パターン | 検出目的 |
|---------|---------|
| 空入力 | 空 map の扱い |
| 全ユニーク | 衝突なし |
| 全同一キー | カウント集約 |
| キー 0 / 負数 | ハッシュ関数・符号 |
| 大きなキー空間 | メモリ（P2） |
| 削除・上書き | get-or-default 漏れ |

## 二分探索との組み合わせ

- ソート済み配列 + lower/upper bound → [binary-search.md](binary-search.md) も読む
- 「ソートしてから解く」問題: ソート前後で index の意味が変わる点を TC で固定

## ストレス（P2）

| パターン | 目的 |
|---------|------|
| N=10^5 ランダム | TLE 検出 |
| 逆順 + クイックソート実装 | 意図的 O(N²) |
| 高衝突入力（設計可能なら） | ハッシュ退化 |
