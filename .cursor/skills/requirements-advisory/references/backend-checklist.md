# Backend Checklist（要件段階）

API・ドメインロジック・データ永続化の観点。

## API・契約

- [ ] エンドポイント / イベントの入出力スキーマは概ね定義できるか
- [ ] バージョニング・後方互換の方針はあるか
- [ ] エラーコード・失敗時レスポンスの一貫性は確保できるか
- [ ] ページネーション・フィルタ・ソートの要否は明確か

## ドメイン・データ

- [ ] エンティティとライフサイクル（作成・更新・削除）は定義されているか
- [ ] トランザクション境界・整合性要件は分かっているか
- [ ] 冪等性が必要な操作は特定されているか
- [ ] マイグレーション・既存データへの影響は触れているか

## 信頼性

- [ ] タイムアウト・リトライ・サーキットブレーカーの方針はあるか
- [ ] 非同期処理・キュー・ワーカーの要否は検討したか
- [ ] 同時実行・競合（楽観ロック等）の扱いは決まっているか

## テスト容易性

- [ ] 境界（HTTP / ドメイン / 永続化）が分離できる設計か
- [ ] テストダブルで検証可能なインターフェースは想定できるか

## 出力

契約・データモデルのビジネス判断 → `UD-*`。技術デフォルト → `AD-*`。
