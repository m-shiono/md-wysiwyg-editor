# Frontend Checklist（要件段階）

UI・クライアント体験の観点。スタックに UI がない場合は N/A とし Trace に記載する。

## ユーザー体験

- [ ] 主要ユーザーフロー（ハッピーパス・エラー）が定義されているか
- [ ] 空状態・ローディング・エラー表示の方針はあるか
- [ ] アクセシビリティの最低要件（キーボード、コントラスト、ラベル）は触れているか

## 状態・データ

- [ ] クライアント状態とサーバー状態の境界は明確か
- [ ] 楽観的更新・競合解決の要否は検討したか
- [ ] オフライン / 低速回線時の挙動は定義されているか

## パフォーマンス・配信

- [ ] 初期表示・インタラクションの許容レイテンシの目安はあるか
- [ ] 静的アセット・キャッシュ方針は `AD-*` で提案できるか
- [ ] 国際化（i18n）・タイムゾーンの要否は明確か

## セキュリティ（クライアント）

- [ ] XSS 対策の前提（サニタイズ、CSP）はあるか
- [ ] クライアントに置いてはいけない秘密情報はないか

## 出力

UX のビジネストレードオフ → `UD-*`。実装パターン → `AD-*`。見落とし → `RK-*`。

実装後の検証: [review-lifecycle.md](../../_shared/review-lifecycle.md) — Post-implementation 列。
