# Blocker Report Template

30 分以上調査しても根本原因が特定できない、またはユーザー判断が必要なときに使用する。
マルチエージェント向けの CSV / inbox ログは使わず、チャットまたは issue コメントにそのまま貼れる形式。

```markdown
## Blocker Report

### 分類
[技術的 / 仕様不明 / 環境 / 外部依存 / テスト設計]

### 問題
[一行要約]

### 期待 vs 実際
- **期待:** [...]
- **実際:** [...]

### エラー詳細
\`\`\`
[スタックトレースまたはテストランナー出力 — doc/stack.md の test_runner]
\`\`\`

### 再現手順（最小）
1. [...]
2. [...]
3. [...]

### 調査済み（証拠付き）
| # | 試したこと | 結果 |
|---|-----------|------|
| 1 | [...] | [...] |
| 2 | [...] | [...] |

### 残る仮説
- **A:** [...] — 未検証理由: [...]
- **B:** [...] — 未検証理由: [...]

### 判断が必要なこと
- [ ] [ユーザーに選んでほしい Option A / B]
- [ ] [不足している情報・権限・アクセス]

### 推奨
[エージェントとしての推奨と理由]

### 待ち時間中にできること（任意）
- [...]
```

## エスカレーション基準

**ユーザーに必ず確認:**

- 仕様変更・スコープ変更が必要
- セキュリティ / 本番データに触れる操作
- 納期・優先度に影響する重大問題

**エスカレーション不要（自律継続可）:**

- 技術的代替案で解決可能
- testspec / systemspec の軽微な追記で解消
- 単一ファイル・単一 TC の修正で完結
